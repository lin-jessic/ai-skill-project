# OpenShop LIFE Studio v2 🏙️

### 從一個開店想法，到一間店的完整人生模擬

**臺灣實體店鋪創業規劃 × 六大 Skill 功能 × 三角色 AI 協作 × 商圈比較 × 每日營運決策**

> 「如果我有 80 萬元，想在桃園開一家手搖飲店，我該選哪個商圈？需要辦哪些手續？要不要加入外送？開幕後能撐多久？」
>
> OpenShop LIFE 將開店問題轉換成可上傳資料、可調整參數、可檢查假設、可匯出成果的互動模擬流程。

**版本定位：** `v2` 為開店模擬器；同一個 GitHub 儲存庫的 `v1` 為獨立的 SafeRoad 交通事故分析專案。兩個版本不互相依賴。

## 📌 專案規模與架構

| 項目 | 數量 | 說明 |
|---|---:|---|
| 主 AI Skill | **1** | `store-opening-advisor`，使用 `SKILL.md` 定義啟動條件、執行規則與交接格式 |
| 三角色 Agent | **3** | 市場分析 → 法規合規 → 開店程序及品質審查 |
| Skill 功能領域 | **6** | 開店法規、員工設備、老闆經營、商圈選址、外送市場、內用／外帶策略 |
| 支援店鋪 | **20 種** | 餐飲、零售、服務三大分類 |
| Dashboard 功能頁 | **7 頁** | 資料挑戰、商圈 PK、法規通關、店面策略、每日經營、財務、報告／測試 |
| 上傳格式 | **CSV / JSON** | 可由教授提供檔案，完成三角色分析與成果匯出 |

> **關於「6 個 Skill」的說明：** 六項是我們規劃與實作的 **Skill 專業功能／能力模組**，目前並非六份可各自獨立觸發的 `SKILL.md`。正式技術架構是 **1 個主 Skill + 3 個 Agent + 6 大功能領域**，避免混淆作業要求與實際程式。

## ✨ 六大 Skill 功能領域

| Skill 功能 | 主要用途 | 互動與成果 | 實作定位 |
|---|---|---|---|
| **Skill 01｜開店法規顧問** | 商業登記、稅籍、食品業者、消防、建管與必要證照的檢核 | 依店型與縣市產生法規清單、風險標記、官方查詢入口 | 已有規則式清單；個案合法性須主管機關確認 |
| **Skill 02｜店員與設備管理** | 食材衛生、設備、人員訓練、營運基本 SOP | 依店型展示員工任務與設備管理項目 | 已有基本 SOP；非個別店家的正式稽核證明 |
| **Skill 03｜老闆經營模擬** | 售價、租金、人事、原物料、營收、毛利、損益兩平 | 財務參數可調、圖表分析、每日開店決策模擬 | 已有情境模擬；預設數值是教學假設 |
| **Skill 04｜智慧商圈選址** | 比較人口、競爭商家、人流指標與租金 | 上傳商圈資料、調整權重、查看相對排名 | 已有資料驅動相對排行；不等於真實獲利機率 |
| **Skill 05｜外送市場分析** | 外送通路、平台費率、包材、外送訂單占比 | 調整外送比例與費用，觀察收益變化 | 已有成本情境；尚無全臺即時訂單／地址覆蓋資料 |
| **Skill 06｜內用／外帶策略** | 座位經營、外帶與外送的模式比較 | 調整不同銷售模式比例，觀察財務結果 | 情境模擬，**不宣稱**預測特定商圈真實顧客偏好 |

## 🤖 一個主 Skill，三個 Agent 如何合作？

```text
使用者提供：店型、縣市、預算、預計開幕日、商圈 CSV / JSON
                           │
                           ▼
Agent 1｜市場分析員（Market Analyst）
  - 檢查資料品質、欄位、數值與來源
  - 比較人口、同業數、人流指標、租金
  - 產生商圈相對評分與市場報告
                           │ 01_market_report.json
                           ▼
Agent 2｜法規合規顧問（Legal Advisor）
  - 依店型與地點列出應確認的法規及主管機關
  - 標記高／中／低風險與未確認事項
                           │ 02_legal_checklist.json
                           ▼
Agent 3｜開店程序規劃師兼審查員（Procedure Auditor）
  - 整合前兩階段結果
  - 產生開店待辦、程序及成本檢核
  - 檢查關鍵欄位、法規缺漏與輸出一致性
                           │ 03_store_opening_plan.md + 04_audit.json
                           ▼
商圈排行、財務模擬、逐日營運、成果 ZIP
```

主 Skill 定義見 [`SKILL.md`](SKILL.md)，角色提示文件位於 [`agents/`](agents/)。**Dashboard 內執行 Python 流水線，不等於已證明 AI 模型自動載入 Skill。** 正式提交須額外完成 AI 工具中 A／B／C 觸發測試並留存證據。

## 🕹️ 七個互動頁面

| 頁面 | 使用者操作 | 畫面成果 |
|---|---|---|
| **01｜資料挑戰** | 匯入 CSV/JSON；設定店型、地點、預算；啟動三角色 | 資料檢查、來源訊息、分析輸出 |
| **02｜商圈 PK** | 調整人口、競爭、人流、租金權重 | 商圈相對排行、視覺化比較 |
| **03｜法規通關** | 查看店型適用項目及待確認事項 | 法規清單、風險資訊、查詢入口 |
| **04｜店面策略** | 變更店面／通路經營參數 | 內用、外帶、外送策略比較 |
| **05｜每日經營** | 選擇每日管理決策，或執行多日模擬 | 訂單、損益、現金變化及模擬事件 |
| **06｜老闆財務** | 修改售價、成本、租金、員工等條件 | 營業損益、損益平衡與敏感度圖 |
| **07｜報告／測試** | 查看審查、下載成果 | 三角色檔案及 ZIP 證據包 |

每日營運模擬使用可重現的亂數機制與假設參數；**不是對未來真實營收的預測**。

## 🚀 安裝及啟動（Windows / VS Code）

### 1. 進入專案的 `v2` 資料夾

```cmd
cd /d C:\path\to\three-agent-skill\v2
```

請將路徑改為你電腦實際位置。Python 建議使用 3.10 以上版本，依 `requirements.txt` 安裝套件。

### 2. 安裝套件

```cmd
python -m pip install -r requirements.txt
```

### 3. 啟動新版 Dashboard

```cmd
python -m streamlit run app.py
```

也可直接雙擊：**`啟動OpenShop_新版.cmd`**。

> 正式新版入口是 **`v2/app.py`**；`app_legacy.py` 為保留的舊版頁面，請勿誤開。

### 4. 測試程式

```cmd
python -m pytest -q
```

## 📂 教授 Demo：上傳一份檔案，實際執行一次

### 支援的輸入格式

- **CSV**：UTF-8、UTF-8-SIG；程式亦嘗試常見的繁體中文編碼。
- **JSON**：紀錄陣列，或物件中的 `records`／`data` 陣列。
- 檔案大小上限：**20 MB**；候選資料上限：**10,000 列**。

至少需要下列欄位：

| 欄位 | 說明 | 單位／注意事項 |
|---|---|---|
| `district` | 候選商圈或地區名稱 | 不得空白 |
| `population` | 同一空間範圍內的人口 | 人；來源與時間需標記 |
| `competitors` | 同類型競爭店家數 | 家／登記列；定義需一致 |
| `footfall` | 交通、人流代理指標 | 同一統計期間；不等於到店客數 |
| `rent` | 預估店面月租金 | 新臺幣元／月 |
| `data_source` | 資料來源（建議） | 官方網址／調查來源／教學假設 |

程式可辨識部分中文欄位別名；不符合規格的未知資料仍需要先轉換。缺值、負數或不能解析的數值不會被私自補成假資料。詳見 [`docs/上傳檔案欄位格式.md`](docs/上傳檔案欄位格式.md)。

**教學示範檔：** [`examples/DEMO_商圈資料_情境假設_非官方.csv`](examples/DEMO_商圈資料_情境假設_非官方.csv)。此檔是**為測試流程而設計的合成情境資料，絕非官方市場統計**。

### 網頁 Demo 順序

1. 在左側選擇店型、縣市、預算等條件。
2. 開啟「01 資料挑戰」，上傳老師提供的 CSV／JSON。
3. 確認資料品質訊息後按下「開始三角色完整審查」。
4. 依序展示 Agent 1 商圈分析、Agent 2 合規檢核、Agent 3 程序及審查。
5. 到商圈 PK 調整權重，展示排行變化。
6. 在每日經營做一次決策，再展示財務情境。
7. 到報告頁匯出成果檔案，檢查稽核狀態。

### 使用終端機跑同一份檔案

```cmd
python -m scripts.run_studio --input examples/DEMO_商圈資料_情境假設_非官方.csv --shop 手搖飲店 --city 桃園市
```

若要測試老師提供的檔案，將 `--input` 改成該檔案路徑。CLI 預設將結果寫至 `outputs/studio_cli/`。

### 主要輸出

| 檔案 | 內容 |
|---|---|
| `01_market_report.json` | 市場、商圈與資料品質分析 |
| `02_legal_checklist.json` | 法規檢查及待主管機關確認事項 |
| `03_store_opening_plan.md` | 開店程序、注意事項及審查說明 |
| `04_audit.json` | 三角色資料交接與審查狀態 |
| `05_finance.json` | 經營與財務情境模型 |
| `06_location_ranking.csv` | 根據匯入檔案計算的商圈排行 |

這些檔案會由實際執行的輸出資料夾產生；ZIP 內預留的示範輸出不應冒充教授現場測試證據。

## 🗃️ 官方資料來源與透明度

OpenShop LIFE 支援將公開統計整理為商圈比較的輸入資料，但**政府原始資料的欄位、地理範圍與時間粒度不同，不能直接把五份 CSV 任意相加**。必須先確認使用的欄位、統計期間、空間範圍、來源與授權。

| 類別 | 官方入口 | 用途／限制 |
|---|---|---|
| 全國營業稅籍登記 | [政府資料集 9400](https://data.gov.tw/dataset/9400) | 觀察登記商家分布；登記數不等於實際到店競品數 |
| 村里人口 | [政府資料集 77132](https://data.gov.tw/dataset/77132) | 潛在客群背景；人口不是實際顧客數 |
| 商業登記統計 | [政府資料集 25346](https://data.gov.tw/dataset/25346) | 產業家數背景比較，須核對縣市／月份 |
| 桃園捷運運量 | [政府資料集 164957](https://data.gov.tw/dataset/164957) | 車站活動代理指標；旅客不等於進店人數 |
| 餐飲業經營統計 | [政府資料集 94937](https://data.gov.tw/dataset/94937) | 產業經營背景，不代表任一店面的實際營收 |
| 商業設立流程 | [經濟部公司與商業一站式申請](https://onestop.nat.gov.tw/) | 行政程序及設立查核入口 |
| 食品相關規範 | [衛生福利部食品藥物管理署](https://www.fda.gov.tw/) | 食品業者登錄、衛生管理，需確認適用情況 |
| 勞動條件 | [勞動部法令查詢系統](https://laws.mol.gov.tw/) | 工時、工資與其他僱用規定 |
| 稅務 | [財政部稅務入口](https://www.etax.nat.gov.tw/) | 稅務與登記資訊 |

優先使用官方入口，而非未查證的深層檔案連結。下載器位於 `scripts/download_official.py`；**若政府主機拒絕下載或連結失效，須在執行紀錄中標記失敗，不能宣稱資料已成功下載**。自動下載不代表資料已完成清理，也不保證已接上全部視覺化。

建議每份匯入資料保留：來源網址、下載日期、統計期間、地理範圍、欄位定義及檔案雜湊值。

## 🧪 Skill 啟動測試（教授評分重點）

正式的 `SKILL.md` 對應 **1 個主 Skill 的啟動邊界**。建議在真正支援 Skills 的 AI 執行環境中，保留以下 A／B／C 三組證據：

| 案例 | 測試提示 | 預期行為 |
|---|---|---|
| **A：明確觸發** | 「我要在桃園開手搖飲店，請比較商圈、法規和開店流程。」 | 載入 `store-opening-advisor` |
| **B：改寫觸發** | 「手上有 80 萬想租間咖啡廳，不知道客群、證照和準備順序。」 | 仍應載入相同 Skill |
| **C：不應觸發** | 「請幫我的貓咪寫生日祝福。」 | 不應載入開店 Skill |

**注意：** 網頁上的「執行三角色」按鈕只是呼叫分析程式，不是 AI Skill 自動啟動的證據。必須另外截取實際 Skill 載入的紀錄，不能以手動執行冒充自動觸發。

## ⚠️ 使用界線

本專案屬於大數據應用課程的研究與教學原型，不是正式法律意見、政府審核、商業投資保證或即時商圈需求預測。選址分數是依選定資料與權重計算的相對指標；輸入資料不完整時應暫停排名或標示限制。對應店址的土地使用、建管、消防、食品衛生及其他許可事項，仍須主管機關按個案核實。
